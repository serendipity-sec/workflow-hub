# 워커 실행기와 작업 API

[계약](contract.md)을 읽고 저장소 루트에서 `worker/`로 이동해 Node.js 24.14.0으로 설치합니다.

```sh
cd worker
npm ci
npm run verify
node dist/cli.js local fixtures/task.json
node --test test/runner.test.mjs
```

`local`은 로컬 파일 경로를 가진 작업 JSON을 받고, 현재 디렉터리에서 상대 경로를 해석합니다. 파일을 한 번 열어 크기를 제한하며 읽은 바이트와 작업의 SHA-256을 대조합니다. 작업 본문의 lease는 만료되지 않아야 합니다. [Postgres 정적 규칙](analysis.md)의 결과는 표준 출력으로 반환합니다. 분석 상태가 `error`이면 종료 코드 1을 반환합니다. 지원 범위 밖인 경우 결과에 `unsupported`와 원인을 기록합니다.

## 계약 모의 서버

`test/runner.test.mjs`는 숫자 루프백 주소에서 임시 모의 서버를 띄워 CLI의 작업 요청 → 파일 다운로드 → 해시 확인 → 자식 프로세스 실행 → 결과 제출을 검증합니다. 개발용 서버를 직접 띄울 때도 같은 경로를 쓸 수 있습니다. 모의 서버 주소로 `WORKER_API_ORIGIN`과 `WORKER_FILE_ORIGIN`을 지정하고 `WORKER_API_TOKEN`에는 합성 토큰을 사용합니다.

```sh
node dist/cli.js mock-once
```

작업을 한 번만 요청하고 HTTP 204는 `idle`로 처리합니다. 상태가 불확실한 claim은 반복하지 않습니다. API에만 서비스 토큰을 전달하며, 파일 요청은 별도 설정한 정확한 origin과 `identity` 콘텐츠 인코딩에 한정합니다. 두 역할 모두 리디렉션을 따르지 않습니다. HTTPS 팀 모드는 코드의 클라이언트만 제공합니다.

서버 수락은 HTTP 201, 이미 수락한 동일 제출의 재전송은 200으로 구분합니다. 두 응답의 본문은 비어 있어야 합니다. 제출의 일시적 HTTP 상태 또는 전송 실패에는 lease가 허용하는 경우 같은 본문과 동일한 멱등 키로 최대 한 번 다시 보냅니다. 요청 중 lease가 끝나면 추가 전송을 중단합니다. 작업·시도·버전 식별자는 작업 API가 부여한 값을 그대로 사용합니다. 서버만 임대 상태와 수락 여부를 확정합니다. 오류 로그에는 고정 사유 코드만 기록합니다.

## 프로세스 범위와 팀 격리

개발용 자식 프로세스는 서버가 정한 경로의 번들 분석기만 실행합니다. 표준 입력으로 작업 식별값과 실제 바이트를 전달하고 임시 파일을 생성하지 않습니다. 엔드포인트·경로·토큰·환경 변수는 분석기에 전달하지 않습니다. Node 권한 모델이 실행 파일·의존성을 읽는 범위를 제한하며 파일 쓰기와 추가 자식 실행을 차단합니다. 컨트롤러는 시간, 표준 출력과 표준 오류의 합, 출력 JSON의 스키마와 식별값을 검증합니다. 개발용 프로그램은 종료 신호나 제한 초과 때 자식을 종료하고 닫힐 때까지 기다립니다. V8 메모리 제한은 전체 프로세스 메모리 상한과 별개입니다.

`runRemoteOnce`는 숫자 루프백 모의 서버의 작업을 받습니다. 팀 HTTPS 모드는 클라이언트만 제공하며, 실행기는 작업을 받기 전에 `isolation_unverified`를 반환합니다. 팀 환경에서 실행을 연결할 때 [계약의 자원 제한](contract.md#팀-api-접점), 네트워크 차단, 비특권 실행, 읽기 전용 파일시스템과 취소 후 자원 회수를 확인해야 합니다. 다음 작업을 받기 전에 종료와 정리가 끝났는지 확인하는 것도 팀 실행기 계약에 포함합니다. 팀 환경의 자원 제한과 실제 팀 API 요청은 아직 검증하지 못했습니다.
