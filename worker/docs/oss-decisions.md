## Gitleaks 실행 계약

- 운영자 설정의 실행 파일만 사용하며 입력 JSON에서 명령·옵션·설정 경로를 받지 않는다.
- 실행 파일 버전이 8.30.1인지 확인한다. 준비 시 공식 배포물과 체크섬을 확인하며, 바이너리는 저장소에 넣지 않는다.
- 기본 규칙을 사용하는 임시 신뢰 설정과 빈 ignore 파일을 명시한다. 환경변수나 현재 디렉터리의 사용자 설정을 상속하지 않는다.
- `stdin`, JSON 결과, 100% 마스킹, 고정 종료 코드와 시간 제한을 사용한다. `gitleaks:allow`로 입력이 검사를 억제할 수 없게 한다.
- 문자열은 디코딩한 값으로 검사하고 결과 위치를 입력 필드 인덱스로 대응한다. 원본 값·도구의 원문 메시지·stderr는 서비스 결과에 전달하지 않는다.
- 다중 인코딩/압축 내부의 비밀정보는 이 프로파일의 지원 범위가 아니다. 해석하지 못한 부분을 전체 검사 완료로 표현하지 않는다.
- 도구 부재, 버전 불일치, 비정상 종료, 잘못된 JSON, 출력/시간 제한은 검사 오류다. 발견 0개와 구분한다.
- 자식 종료를 기다린 뒤 임시 설정 파일을 정리한다. 사용자 워크플로 본문은 임시 파일에 저장하지 않는다.

로컬에서 사용한 Windows 실행 파일의 SHA-256은 `17157e2ee8b76fc8b1d8bee607a250e34b8a8023c8bc81822d4b5ee4d78fcb7c`다. 이 값은 다른 운영체제의 바이너리에 적용하지 않는다.

## 개인정보 판정 범위

지원한 형식의 후보만 반환하고 값은 마스킹한다. 테스트용·예시용 값도 실제 개인정보라고 확정하지 않는다. 노드 자격 증명 참조의 이름이나 워크플로의 구조 ID는 그 자체로 실제 비밀정보라고 판단하지 않는다. 필드명이 아니라 값의 검증 결과와 필드 위치를 함께 사용한다.

형식 검증 라이브러리는 후보 문자열을 찾아주는 NER 엔진이 아니다. 후보 추출·최대 길이·필드 수 제한과 JSON 위치 연결은 워커가 담당한다. 지원 언어/유형 밖의 이름·주소·주민등록번호 등은 확인하지 않은 범위로 남긴다.

## 실제 도구 실행 검증

운영자가 신뢰한 Gitleaks 8.30.1의 절대 경로를 `WORKER_GITLEAKS_PATH`로 제공한 뒤 `worker/`에서 실행한다. 바이너리를 찾지 못하면 시험을 실패시키며 다른 도구나 가짜 결과로 대체하지 않는다.

```text
npm run build
node validation/verify-static-tools.mjs
```

기본 결과는 `evidence-local/static-tool-results.json`에 기록한다. 검증한 기준 기록은 [static-tool-results.json](../validation/static-tool-results.json)에 보존했다. 합성 입력만 사용한 7개 사례에서 일반 문자열 0건, 문자열 키/다중 행의 후보 위치 대응, `gitleaks:allow`와 외부 환경 설정에 의한 억제 방지, 출력 제한·도구 부재·취소의 오류 상태, 실제 도구와 개인정보 검사 통합을 확인했다. 기록에는 입력·바이너리 해시, 버전, 고정 인자와 결과 수만 포함하며 값 원문은 포함하지 않는다.

내용 검사 단위 테스트는 잘못된 도구 버전/필드 인덱스와 후보 수 제한을 포함한다. 네이티브 도구의 모든 실패·플랫폼 조합을 실측했다는 뜻은 아니다. 서로 다른 파일의 내용 후보가 사라졌다고 해서 실제 비밀정보 폐기나 개인정보 제거의 효과를 자동 확정하지 않는다. 현재 일반 비교기는 해당 변화의 대응을 보수적으로 유보할 수 있다.

## 공개 템플릿 호환성 검증

`downloads.json`과 숫자 ID별 `<id>.workflow.json` 원본을 가진 로컬 디렉터리를 사용한다. 수정본·작업 파일·이전 결과 파일은 검사 대상에 포함하지 않는다. 검증 스크립트는 파일의 SHA-256·바이트 수가 다운로드 기록과 일치하는지 먼저 확인한다. 원본을 다시 내려받거나 워크플로를 실행하지 않는다.

```text
npm run build
node validation/verify-public-static.mjs <download directory> [report path]
```

이 명령에도 `WORKER_GITLEAKS_PATH`가 필요하다. 실제 Gitleaks 실행 성공, 결과 스키마와 10개 항목의 존재, `execution: not_run`을 확인한다. 실행한 컴파일 모듈·lockfile·검증 스크립트·도구·입력의 해시를 기록하며, 검사 도중 컴파일 모듈이 바뀌면 실패한다. 결과에는 출처 URL과 숫자 ID, 항목별 발견 수·진단 코드·검사 범위 수만 남긴다. 워크플로 본문·노드 이름·JSON 내부 URL·후보 값 원문은 저장하지 않는다.

[public-static-results.json](../validation/public-static-results.json)은 공개 템플릿 5개를 처리한 호환성 기록이다. 각 결과의 `partial`은 미지원 노드·버전·표현식이나 추적 불가능한 경로가 남았다는 뜻이다. 정답이 있는 취약점 평가 집합이 아니므로 탐지 정확도·일반 안전성·공격 차단 효과를 검증한 것으로 해석하지 않는다. 코드가 바뀌면 같은 원본으로 다시 실행해 기록을 갱신한다.
