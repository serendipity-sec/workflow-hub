# 개발 범위와 일정

## 목표

4명이 AI를 활용하여 9~10일 안에 n8n JSON을 업로드하고, 버전 이력을 조회하며 원하는 버전을 다운로드하는 데모를 만든다. 보안 검증의 차별성은 추가 검토 중이며 이번 필수 개발 범위에서 제외한다.

## 확정된 결정

- 임시 프로젝트 이름: workflow-hub. 원격 저장소는 README 검토 후 생성/연결한다.
- 프론트와 백엔드는 이 저장소에 함께 둔다. 보안 워커는 후속 별도 저장소다.
- React/TypeScript/Vite, Spring Boot/Java, Supabase Auth + PostgreSQL, S3.
- Google 로그인, Access Token + Refresh Token Rotation. 토큰 발급과 회전은 Supabase가 담당한다.
- 원본/수정본 JSON은 S3에 보관한다. 이전 기획의 일시 보관 정책은 이 프로젝트에 적용하지 않는다.
- #8: 버전 번호는 워크플로별로 `v1`, `v1.1`, `v1.2`, `v2`처럼 관리한다. 저장된 버전의 파일은 불변이며, 업데이트 시 새 버전과 별도 파일을 추가한다.
- #8: 파생본은 독립 워크플로의 `v1`로 시작한다. 기존 리비전 트리는 DB 모델에 적용하지 않는다. 파생 기능 자체는 후속 구현이다.
- pgvector는 지원 가능한 확장 지점이며 초기 검색 구현 의무가 아니다.
- front/back 영역은 라벨로 구분한다. 커밋 scope는 auth/workflow/revision 등 기능 중심이다.
- Squash merge와 Conventional Commit 형식 PR 제목을 기준으로 한다.
- 최초 push 전에 사용자가 README 초안을 검토한다.

## 구현 순서

| 단계             | 완료 조건                                            | 목표 시점 |
| ---------------- | ---------------------------------------------------- | --------- |
| 기반             | 새 개발자가 문서대로 설치·검사·실행                  | 1일       |
| 개인 업로드/조회 | 로그인 사용자 소유 JSON 저장 및 목록/상세 API와 화면 | 2~3일     |
| 다운로드         | 권한 검사 후 특정 S3 객체 다운로드, 타인 접근 테스트 | 4일       |
| 버전 이력        | 불변 파일, 워크플로별 버전 목록, 새 버전 업로드      | 5~6일     |
| 통합             | 파일 제한·오류·빈 상태·재시도·인증 만료 테스트       | 7일       |
| 배포             | 실제 Google/Supabase/S3 연동 및 데모 전체 흐름       | 8일       |
| 안정화           | 버그 수정, 발표 자료, 예비 시간                      | 9~10일    |

일정은 목표이며 보장치가 아니다. 공개 목록/타인 분기는 개인 흐름 완성 후 추가한다.

## 초기 구현 기본값과 보류 결정

기본값: 개인 비공개 워크플로, 본인 데이터만 조회/수정/다운로드, 워크플로별 독립 버전 이력, 자동 병합 없음. 이는 구현을 진행하기 위한 제한된 기본값이다.

공개 전환, 공개본 재배포, 타인 분기의 소유권·삭제 정책은 구현 전에 별도 결정한다. 라이선스 확인 없이 공개 워크플로를 수집하거나 재배포하지 않는다. 파일 크기 상한·최종 보관 기간은 업로드 기능 작업에서 정하고 API 계약에 반영한다.

## 팀 분담

- Backend/Infra: API·소유권·DB·S3·배포·외부 인증 설정.
- Frontend: 인증 UI, 업로드·목록·상세·버전 이력·다운로드 화면.
- Security A: 안전한 샘플, JSON 구조 검증 계약과 실패 사례. 보안 룰은 연구 작업.
- Security B: 통합 테스트·평가 시나리오·민감정보 처리 검토. 자동 패치는 연구 작업.

보안 담당자의 변경된 배분은 제안이며 팀 조정 가능하다. 계약과 완료 조건으로 작업을 나누고 기술 스택만으로 역할을 고정하지 않는다.

## 이번 기반 작업의 완료 범위

실행 가능한 프론트·백엔드, Google 로그인 연결 코드, JWT 검증과 최소 API, 자동 검사, API 계약, 샘플, 문서와 GitHub 템플릿을 준비한다. #8에서 워크플로·버전 저장용 PostgreSQL 마이그레이션과 실제 DB 통합 테스트를 추가한다. 외부 계정 설정과 실제 워크플로 CRUD API·S3 업로드·버전 서비스는 후속 개발이며 완료된 것으로 표시하지 않는다.
