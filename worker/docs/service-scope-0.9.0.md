# 0.9.0 서비스 범위와 보안 경로 보완

[#14](https://github.com/serendipity-sec/workflow-hub/issues/14)의 기존 `feat/14-integrate-security-worker` 브랜치에서 진행했다. 0.8.0 코드·검증 기록을 보존하고 실제 팀 API 연결 없이 정적 검사와 서비스 설명을 보완했다. 실제 연동은 프론트·백엔드 구현에 맞춰 [#18](https://github.com/serendipity-sec/workflow-hub/issues/18)에서 확인한다.

## 적용한 서비스 결정

| 구분                                             | 초기 서비스의 처리                                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 실제 환경·권한·패키지·네트워크·업무 정책         | 사용자에게 필수 입력을 요구하지 않고 사용 전 주의사항으로 표시                              |
| 개인정보                                         | 기존 형식·문맥 탐지와 유출 후보 검사는 유지. 문맥 모델의 언어·완전성만 미완료 사유에서 제외 |
| 미지원 코드·노드·연결·누락된 하위 정의·처리 한도 | 구체 위치와 분석 공백을 유지하며 추가 보안 검토 필요                                        |
| 높은 심각도의 후보·명시적인 정책 차단/검토       | 범위 안내로 숨기지 않고 `securityReviewRequired: true` 유지                                 |

서비스 설명·묶음은 **1.1.0**이다. `analysisStatus`는 선언한 초기 정적 범위의 완료 여부이며 안전 판정이 아니다. 원본 `assessmentStatus`, 모든 위험 후보, 정책 결정과 생략 수를 보존한다. 과거 0.8.0 및 이전 결과는 기존 **1.0.0** 설명과 LLM 문맥을 재현한다. [표시 계약](service-report.md)과 [서비스 연결 자료](integration-handoff.md)에 프론트의 처리 기준을 적었다.

## 구현으로 보완한 내용

- **Code와 값 흐름:** Acorn AST로 배열 join/slice, 제한된 split/pop, 정규식 match, Date·Math·Number 의존성을 추적한다. 결과 타입·예외·실행 성공을 추측하지 않으며 민감정보 출처와 unknown을 함께 보존한다. `new Date(localAlias)`의 출처 손실도 독립 리뷰에서 찾아 수정했다. [지원 경계](code-builtins.md).
- **마지막 Code의 부수 효과:** 다른 노드가 반환값을 사용하지 않아도 활성 Code 본문을 먼저 해석한다. 고정 `globalThis.eval/Function/fetch`, 구조분해 별칭, n8n HTTP helper와 계산된 console 멤버를 검사한다. 동적 호출·파싱 실패·처리 한도는 실제 분석 공백이다. [Code 위험 검사](advanced-risks.md).
- **로컬 노드와 오류 출력:** Merge append·Limit·SplitOut·ErrorTrigger의 좁은 프로필과 Stop and Error의 메시지·오류 객체를 검사한다. 비밀·개인정보가 오류 출력으로 전달되는 후보를 찾고, 256개 결과 한도에서는 높은 심각도 후보와 생략된 위치를 보존한다. [데이터 효과](data-effects.md).
- **AI·RAG:** Pinecone/Supabase 저장소, 문서 로더·임베딩, MongoDB 메모리·Groq fallback 및 일부 도구 연결을 해석한다. 문서 본문→임베딩 API, 본문+메타데이터→벡터 저장을 나눠 검사한다. 메타데이터가 임베딩 본문에 들어갔다고 과장하지 않는다. [AI 전송 경로](ai-vector-binary.md).
- **바이너리:** 기본 첨부 옵션만으로 파일이 빠졌다고 판단하지 않는다. 알려진 제거·상수 JSON 반환만 제한적으로 부재를 증명한다. pinData, 동적 할당, 미확인 표현식 효과·포트·버전은 부재 증명을 막고 기존 후보와 분석 공백을 유지한다. 파일 내용·실행 중 실제 존재는 별도 주의사항이다.
- **정책·설명:** 정책 자체가 없는 경우와 목적지·데이터 출처를 해석하지 못한 경우를 구분한다. 목적지가 미확정이어도 알려진 금지 데이터 종류는 위반 후보로 남긴다. 정책의 block/review 판정은 중간 심각도만 있더라도 화면의 검토 필요 상태를 유지한다.

기존 node-sql-parser·Gitleaks·Presidio/spaCy·Python AST 검사는 유지했다. 새 라이브러리를 설치했다고 주장하지 않으며 기존 Acorn과 고정 n8n 소스를 사용한 프로필 확장이다. 워크플로·표현식·Code는 실행하지 않았다.

## 검증 근거

- Node 24.14.0에서 워커 format/lint/typecheck/build와 **586/586 테스트**, 루트 check와 도구 **6/6 테스트** 통과.
- 고정 합성 정적 corpus **27/27**, 기존 SQL corpus **12/12** 통과. 예상 오류·미지원도 정해진 상태 검증의 일부이며 일반 탐지율이 아니다.
- 실제 Docker 도구·격리: 합성 assessment **8개·파일 9개**, 격리 **9조건**, 실패·취소 **4조건**, 컨테이너 정리 통과.
- 개인정보·코드 네이티브 프로필 **44개**, 기존 공개 회귀 **54개**, 새 서비스 범위·RAG 회귀 **86개**, 오프라인 설명 **25개**, 통제된 수정본 재검사·비교 **3쌍** 통과.
- 현재 세션의 독립 교차 리뷰에서 출처 손실, 함수 구조분해, 결과 한도, 정책 차단 표시, 바이너리 부재 증명 문제를 수정·재검증했다. AI **75+19**, Code **43+16**, 서비스 **20** 검사는 전체 회귀와 일부 중복되므로 합산한 독립 탐지율로 제시하지 않는다. 검토 범위의 미해결 P1/P2는 없다.

[전체 실행 요약](../validation/service-scope-0.9.0-results.json), [실제 런타임](../validation/assessment-runtime-0.9.0-results.json), [15개](../validation/public-assessment-0.9.0-results.json), [추가 10개](../validation/public-additional-0.9.0-results.json), [서비스 회귀](../validation/service-scope-regressions-0.9.0-results.json), [설명 결과](../validation/inspection-0.9.0-results.json)에 소스·이미지·원본·결과 해시를 연결했다.

0.8.0 기록 당시 별도 CLI 리뷰는 실행 전에 차단됐다. 이후 사용자의 현재 브랜치 커밋·푸시 지시에 따라 현재 세션의 독립 교차 리뷰와 검증으로 진행했다. 별도 CLI 리뷰를 실행했다고 기록하지 않는다.

## 남는 경계

복잡한 반복·객체 변경·동적 SQL·미지원 커넥터, 일반 로그 인자의 지역 별칭, 미제공 하위 정의, 실제 바이너리 내용·모델 행동은 완전히 해석하지 못한다. 실제 보안 경로가 미해석인 경우는 검토 필요로 유지한다. 원본·수정본의 업무 기능 보존이나 배포·화면 E2E도 입증하지 않았다.

이번 0.9.0에서는 새 LLM 호출을 하지 않았다. 기존 [0.8.0의 실제 OpenRouter 3회 검증](../validation/llm-public-three-0.8.0-results.json)은 이전 문맥의 실행 근거로 보존한다. 새 설명 25개의 생성·바인딩은 로컬에서 검증했고, LLM이 미해석 경로를 추측해 해소한 것으로 처리하지 않는다. 실제 팀 API 연동은 별도 후속 작업이다.
