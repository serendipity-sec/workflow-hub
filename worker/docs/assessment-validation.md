## 리뷰와 수정

`codex review --base origin/main`으로 기존 브랜치 커밋과 staged 신규 파일을 포함한 전체 변경을 검토했다. 207개 테스트가 통과한 상태에서도 두 P2 반례가 발견됐다.

- 128개를 넘는 객체의 잘린 필드를 존재하지 않는 공개 값으로 처리하던 문제: 객체 완전성·한도 진단·미확인 민감도를 보존하고 경계값, 중첩 배열/표현식, 덮어쓰기 회귀 사례를 추가했다.
- 비밀정보와 개인정보가 섞인 객체에서 가장 높은 분류 하나만 정책에 넘기던 문제: 모든 분류의 집합을 객체·직렬화·결합을 통해 유지하고 정확한 단일 필드 조회와 구분했다.

수정 후 Node 24 전체 217개 검사가 통과했다. 별도 Codex 후속 리뷰는 해당 수정·회귀 검사, 이미지 무결성·취소 검사와 Gitleaks 정확한 예외를 검토하여 남은 구체적 결함이 없다고 보고했다. 후속 리뷰의 추가 집중 테스트 55개는 그 리뷰 프로세스의 Node 22에서 실행됐으므로 필수 Node 24 검사를 대체하지 않는다. 통합 담당자가 위 Node 24 전체 검사와 실제 Docker 검증을 수행했다.

## 재현과 판정 범위

[통합 실행법](assessment.md)대로 이미지를 준비한 뒤 다음을 실행한다.

```text
npm run verify
node validation/verify-static-corpus.mjs
node validation/verify-assessment-runtime.mjs
node validation/verify-remediation-behavior.mjs
```

네이티브 단독 검증은 [NLP/AST 실행법](native-inspection.md), 이전 Gitleaks 검증은 [도구 문서](oss-decisions.md)를 따른다. 합성 SQL 검증 스크립트는 고정된 PostgreSQL/n8n 이미지를 준비하고, 소유 라벨을 확인한 임시 컨테이너만 제거한다. 정상 조회에서 행이 없는 입력의 기존 HTTP 500도 그대로 보존된 결과이며 성공 응답으로 바꾸지 않았다.

이 결과는 지정한 합성 사례의 관측이다. 전체 워크플로의 탐지율, 임의 프로그램의 동등성, 실제 사용자의 권한/설치 패키지/네트워크, 실제 팀 API, AI 동적 공격 저항성이나 실제 비밀키 유효성을 검증했다는 뜻이 아니다. 제공된 정책·환경·OSV·승인 자료는 출처와 미확인 상태를 유지한다. 단독 개발 브랜치의 새 `Worker assessment` CI는 push 시 별도 실행되며 로컬 결과와 혼동하지 않는다.
