# 0.8.0 공개 25개 `partial` 원인과 보완 결과

[#14](https://github.com/serendipity-sec/workflow-hub/issues/14)의 기존 워커 브랜치에서 0.7.0 확정 원본 25개를 같은 바이트 해시로 다시 검사했다. 원본 워크플로·Code·표현식을 실행하지 않았다. 실제 팀 API 연동과 한국어 개인정보 모델 확대는 이번 범위에 포함하지 않는다.

## 결과를 읽는 기준

최종 이미지 `sha256:28b673341d36a975960e85b9c4fe9c51ed1643b740e3a44c2607eab9532f7d3c`에서 **25개 모두 `partial`**, 입력 거부·검사 오류는 0개다. Gitleaks·Presidio/spaCy·Python AST의 도구 결과 **75건 모두 `completed`**다. `partial`은 검사 실패나 취약점 확정이라는 뜻이 아니라, 일부 규칙에 미확인 범위가 있다는 뜻이다.

전체 원시 진단 발생은 **3,297 → 3,169건**이다. 하나의 노드가 여러 규칙에서 반복되므로 독립 취약점 개수나 탐지 정확도로 해석하면 안 된다. 서비스 카드의 표시 한도와 별개로 모든 규칙을 집계했으며, 미분류 진단과 잘린 원인 코드는 없다.

범주별 해당 사례는 서로 겹친다. 예를 들어 외부 전송 정책이 미확인인 이유가 정책 부재일 수도 있고, 목적지 값을 해석하지 못했기 때문일 수도 있다. 이를 모두 “사용자가 환경 정보를 입력하면 해결”로 분류하지 않는다. 필요한 근거는 비밀키나 개인정보 원문이 아니라 운영자가 확인한 접근 범위·정책·익명화한 구조다. 이 자료 제출을 서비스의 필수 입력으로 결정한 것은 아니다.

## 구현으로 보완한 부분

- **Set·Switch·Aggregate:** 고정 n8n 소스의 버전·옵션·포트 의미와 기존 Acorn AST를 사용해 제한된 로컬 데이터 처리 프로필을 추가했다. 불투명한 노드 효과 진단은 **1,154 → 1,030건**으로 줄었다. Set/Aggregate 이후 현재 값이 원본과 같다고 가정하거나 Switch를 보안 검증 조건으로 승격하지 않는다.
- **Code 배열·분기:** `filter(Boolean)`, 명명된 순수 콜백, `some`·`every`·제한된 `flatMap`, 불변 기본값 캡처, 단일 `JSON.parse` 예외 처리, 최상위 `await` 파싱을 보완했다. 필터링 후 바뀐 위치, 조건부 필드, 분기 병합과 JSON 재파싱에서도 민감 출처 후보를 보존한다. 무관한 형제 필드의 분류를 가져오는 오탐과 다른 배열 위치의 guard를 재사용하는 문제도 회귀 검사한다.
- **AI 예제 스키마:** 고정된 평면 JSON 예제에서 구조만 확인하는 좁은 프로필을 추가했다. 5819의 해당 미확인 진단 1건을 해소했다. 예제 내용이 실제 모델에 전송된 데이터라고 간주하지 않는다.
- **사용자 설명:** `coverage` 명령과 `buildCoverageExplanation`으로 환경·정의·구현·혼합·범위를 구분하고 원래 파일·분석·규칙·진단을 참조한다. 원래 판정과 실패 상태, 생략 수를 보존한다.

새 구문이 해석되면서 다음 단계의 미확인 진단이 드러난 사례도 있다. Code 진단 전체를 무조건 감소시키거나 안전한 것으로 처리하지 않았다. `code_parse_unavailable`은 1 → 0이지만, 반환 구조·컬렉션 상태·추상 형태 예산 등의 한계는 남는다. 자세한 양성·음성·미지원 경계와 단계별 근거는 [Code 분석](bounded-code-collections.md), [로컬 데이터 효과](data-effects.md), [AI 예제](ai-example-schema.md)를 참조한다.

20541 `/nodes/13`의 새 형태 제한은 실제 데이터 크기 문제가 아니라 정적 상태의 최소 529개 구조가 512개 예산을 넘은 경우다. 해당 사례의 개인정보 전송 후보는 10 → 10으로 유지됐다. 11007 `/nodes/19`의 새 빈 컬렉션 진단은 `|| []` 대안을 보존한 결과다. 작은 AST 합성 반례에서도 빈 배열 가능성과 함께 internal 분류와 원출처가 유지됐다. 이 두 사례를 도구 실패나 위험 해소로 집계하지 않는다.

## 오픈소스와 LLM의 역할

Acorn 8.19.0을 실제 구문 해석에 재사용했고, 기존 node-sql-parser·Gitleaks·Presidio/spaCy·Python AST 검사는 유지했다. n8n의 고정 소스에서 확인한 의미를 제한된 정적 프로필로 구현했다. 새로운 범용 라이브러리를 설치했다고 주장하지 않는다. 도구별 역할과 원문 근거는 [OSS 결정](oss-decisions.md)에 연결했다.

기존 OpenRouter `z-ai/glm-5.3-flash`에 보완 후 대표 3개(18521·11007·5819)의 최소 요약을 전송했다. 세 호출 모두 스키마와 기존 근거 참조 검증을 통과했고, 선택한 진단에 고정 조치 3·3·5개를 연결했다. 보고된 총 비용은 USD 0.0005385597이다. 이전 25회 호출과 별도의 새 3회 검증이다.

모델은 원본 JSON·Code·이름·주소·키·원본 해시를 받지 않는다. 기존 근거를 선택하고 설명 순서를 돕는 역할이며, `analysisGapResolved: false`와 원래 `partial`을 유지한다. 실제 권한이나 미지원 코드의 의미를 모델이 추측해 검사 완료로 바꾸지 않는다. 근거 선택의 일반적인 품질·우선순위 최적성은 측정하지 않았다.

## 검증과 남은 조건

- Node 24.14.0에서 워커 format/lint/typecheck/build와 **529/529 테스트**, 루트 check와 도구 **6/6 테스트** 통과.
- 정적 합성 corpus **27/27** 통과. 사전에 정한 사실 23개는 TP 13·TN 10·FP 0·FN 0이며 별도 상태 사례 4개를 포함한다. 예상된 거부/오류 처리도 통과 기준에 포함하며 일반 탐지율이 아니다.
- 새 Docker 이미지의 합성 assessment 8개·파일 9개, 격리 9조건·실패 4조건·컨테이너 정리 통과.
- 공개 원본 25개 재검사, 오프라인 설명 25개, 기존 공개 회귀 **54개**, 원본/통제된 수정본 비교 **3쌍** 통과. 원본은 보존했으며 업무 기능 보존은 검증하지 않았다.
- 독립 내부 리뷰에서 발견한 출처·분기·위치·선택적 필드 문제를 수정하고 전용 **33개** 검사를 재통과했다. 검토 범위의 미해결 P1/P2는 없다.
- 별도 Codex CLI `/review`는 외부 사설 코드 전송 승인 부족으로 자동 승인 검토에서 차단됐다. 해당 리뷰 실행 또는 사용자의 명시적 절차 예외가 확인되기 전에는 커밋 완료로 기록하지 않는다.
