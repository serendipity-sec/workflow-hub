# n8n 입력 정규화

`parseWorkflow`는 런타임에서 해시를 확인한 원본 바이트를 받는다. 바이트 제한과 UTF-8을 검사한 뒤 컨테이너 중첩 깊이 및 디코딩한 객체 키의 중복을 확인한다. 예를 들어 `nodes`와 `\u006eodes`는 동일한 키다. 입력 숫자, 키 순서, 공백을 바꾸어 원본 파일의 해시를 다시 정의하지 않는다.

정규화 그래프는 노드 ID, 표시 이름, n8n `typeVersion`, 활성 상태, JSON Pointer를 보존한다. 노드 키는 ID의 SHA-256이며 표시 이름이나 배열 순서 변경의 영향을 받지 않는다. ID 또는 이름이 충돌하거나 연결에 존재하지 않는 노드, 고정 n8n 버전에서 정의하지 않은 채널 또는 잘못된 포트가 지정된 파일은 오류로 반환한다. 빈 분기에는 n8n이 직렬화하는 `null`을 허용하며, IF의 true/false 출력 번호는 0/1을 유지한다. AI 등 정의된 `main` 이외 채널의 연결도 별도로 보존한다. [고정 n8n 연결 형식](https://github.com/n8n-io/n8n/blob/86dff76e10efba250a4d3e57760e4eb5d2bbea25/packages/workflow/src/interfaces.ts#L515-L543) · [채널 목록](https://github.com/n8n-io/n8n/blob/86dff76e10efba250a4d3e57760e4eb5d2bbea25/packages/workflow/src/interfaces.ts#L3115-L3136).

지원 표의 표현식은 현재 아이템 필드 참조와 이전 노드의 첫 아이템 직접 참조로만 읽는다. IF의 검사 필드와 명시적으로 `database`의 `executeQuery`를 선택한 Postgres의 쿼리 및 파라미터에서 제한된 참조를 해당 필드 위치와 연결한다. 표현식, Code, 하위 워크플로를 실행하거나 값을 얻기 위해 외부에 접속하는 과정은 없다. 쿼리와 IF의 조건 및 지배하는 분기는 규칙에서 판정한다.

미지원 노드·버전·이름을 해석할 수 없는 참조·비활성 노드·외부 하위 워크플로·미지원 연결은 위치와 영향 노드 키를 남긴다. 영향 범위는 실행 연결과 직접 참조를 따라 계산하며, 워크플로 전체 설정이나 핀 데이터는 전체 그래프에 영향을 준다. 그래프의 원본 노드 이름, 옵션과 표현식은 분석 프로세스 안에 있으며 결과 스키마에는 고정 위치와 키만 포함된다.

`npm run verify`가 정규화 단위 테스트를 포함한다. 빌드 뒤 `node --test test/n8n.test.mjs`로 해당 테스트만 실행할 수 있다.
