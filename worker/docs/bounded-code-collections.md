# Code 컬렉션과 제한 예외 흐름 보완

이 문서는 #14의 정적 Code 분석 보완 범위다. 기존 Acorn AST와 `bounded-code.ts`의 제한된 추상값 전달을 사용한다. 제출된 JavaScript, 콜백, 워크플로는 실행하지 않으며 새 의존성을 추가하지 않는다. 원본 출력의 정상 동작을 입증하는 실행 검증과는 구분한다.

## 구현 범위

| 구문                                                  | 분석하는 내용                                                      | 남기는 한계                                                                       |
| ----------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| `values.filter(Boolean)`                              | 가능한 모든 원소의 출처·민감 분류를 유지                           | 참/거짓 선택을 정화나 검증으로 취급하지 않고, 원소 수·위치 이동을 미확인으로 남김 |
| 명명된 순수 함수의 `map`·`filter` 등 콜백             | 선언 위치에서 포착한 불변 기본값과 기존 순수 함수 프로파일 재사용  | 변경 가능한 캡처·객체 캡처·외부 효과·호출자 인자에 의한 함수 가림은 계속 미지원   |
| `some`·`every`                                        | 입력과 콜백의 가능한 데이터 의존성을 유지한 스칼라 결과            | 실제 불리언 값과 단락 평가 횟수를 확정하지 않고, 검증 조건을 생성하지 않음        |
| `flatMap`                                             | 반환된 배열·스칼라의 가능한 분류를 함께 보존                       | 런타임 형태와 배열 길이·위치가 미확인이며 정확한 원소를 단정하지 않음             |
| 콜백의 세 번째 인자                                   | 원래 컬렉션을 전달                                                 | 두 번째 인덱스는 계속 미확인                                                      |
| 기본값으로 확정된 계산 속성                           | 불변 캡처 등의 문자열·숫자 인덱스를 기존 안전한 필드 투영기로 전달 | 동적 인덱스·`__proto__`·`prototype`·`constructor`는 허용하지 않음                 |
| 제한된 `try { result = JSON.parse(raw) } catch { … }` | 성공 결과와 실패 대체값을 병합하고 독립된 공개 필드를 구분         | 파싱한 동적 내용의 구조·실제 성공 여부는 미확인                                   |

JSON 예외 프로파일은 try 본문이 **단 하나의 `JSON.parse` 반환 또는 가변 식별자 대입**일 때만 적용한다. 인자는 식별자 또는 리터럴 하나이며, 예외 변수를 사용하지 않고 `finally`가 없어야 한다. 이 범위에서는 대입이 파싱 성공 후에만 반영되므로 실패 분기를 대입 전 상태에서 분석할 수 있다. 중간 쓰기가 있는 여러 문장, reviver, 입력 계산 호출, 예외 객체 참조, `finally`와 외부 효과는 기존 보수적 프로파일을 유지한다.

콜백에 추가 `thisArg`를 제공하거나 일반 `reduce`·`forEach`로 상태를 변경하는 경우를 새 지원으로 취급하지 않는다. AST 노드·전달 단계·형태 크기·요청 전체 예산은 그대로 유지한다. 배열 콜백의 인자와 `flatMap`의 한 단계 평탄화 의미는 [ECMAScript 배열 명세](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array.prototype.map), 예외 흐름은 [try 명세](https://tc39.es/ecma262/multipage/ecmascript-language-statements-and-declarations.html#sec-try-statement)를 기준으로 제한했다.

## 1차 검증과 실제 사례

`test/bounded-code-collections.test.mjs`는 정상 기본값, 비밀값 출처, 위험한 속성 키, 선언 위치의 캡처와 호출자 가림, 배열 인자, 외부 효과, 변경 가능한 캡처, 미지원 reducer, JSON 예외 분기와 중간 쓰기를 검사한다. 기존 `value-flow.test.mjs`의 단일 parse/catch 기대값은 민감 결과를 유지하면서 독립된 `fixed: 'public'` 필드까지 민감하다고 보던 오탐을 수정했다. 전용 10개와 기존 흐름 검사 98개, 총 108개를 통과했다.

자체 리뷰에서는 기존 `filter`가 원래 배열의 위치별 값을 보존하던 문제도 확인했다. `['', password].filter(value => Boolean(value))[0]`처럼 필터링으로 민감한 값이 앞으로 이동할 수 있으므로, 인라인·명명 콜백 모두 가능한 원소들의 합집합으로 변경했다. 배열 위치가 유지된다고 가정해 공개 빈 문자열로 판정하지 않도록 회귀 검사를 추가했다.

공개 원본은 `.runtime/n8n-service-validation-20261123-v070-final` 및 `-final-extra`의 확정 25개만 사용했다. 전체 66개 Code 노드에 대해 기준 커밋 `cf2f5beb941e05cb2fbdac5874be4d06ee9f7f40`의 bounded 모듈과 보완 모듈을 각각 복제한 나머지 동일한 분석 모듈에 연결했다. 원본 실행·LLM 전송 없이 AST 전달 진단만 비교한 결과다. 전체 Docker 검사 결과와는 별도이며 `partial` 해소율을 뜻하지 않는다.

## await와 AI 예제를 포함한 2차 검증

독립 리뷰에서 대표 원소 변경이 미확인 컬렉션의 후속 `password` 필드 후보를 누락시키는 경우를 확인해 수정했다. 정확한 인덱스를 만들지 않고 기존 필드 이름 분류기를 적용하여 알려진 컬렉션 출처 접두사와 민감 후보를 유지한다. Webhook → Code `filter` → Slack 전송 회귀로 위험 후보가 이어지는지 확인했다.

최상위 `await`는 [고정 n8n JavaScriptSandbox](https://github.com/n8n-io/n8n/blob/86dff76e10efba250a4d3e57760e4eb5d2bbea25/packages/nodes-base/nodes/Code/JavaScriptSandbox.ts)의 async 함수 감싸기에 맞춰 파싱한다. `static-settings.ts`와 `advanced-risks.ts`는 이미 같은 Acorn 옵션을 사용하고 있었다. `value-flow.ts`의 두 Code 파싱 경로를 맞췄고, 인자의 출처를 전달하되 thenable 해석·거부·실행 성공은 `code_await_result_unverified`로 남긴다. 일반 동기 함수 안의 잘못된 await는 구문 오류이며 비동기 함수 선언·콜백 자체는 기존 미지원 범위를 유지한다.

이 단계의 전용 Code 검사는 13개, 기존 흐름은 98개로 총 111개다. [AI 예제 보완](ai-example-schema.md)의 전용 5개와 기존 AI·설정 검사까지 포함한 관련 검사 180개를 통과했다.

이 단계의 정적 비교는 기준 커밋의 `bounded-code`, `value-flow`, `ai-flow` 세 모듈을 보완 모듈과 비교했다. 확정 25개·Code 66개 중 Code 진단 변화는 앞선 18521·20459에 더해 11007 `/nodes/5`까지 3개 워크플로의 4개 노드다. 11007의 최상위 await는 더 이상 `code_parse_unavailable`가 아니지만 실제 미지원 문장 구조가 남아 `code_statement_profile_unresolved`이고 여전히 `partial`이다. 입력 해시는 `a5b90072022086d7a8529309a0da2968481e902fc6260e4be6646489c0676580`이다. 별도 AI 예제 보완은 5819의 변환 불확실성 진단을 해소했다. 이 직접 정적 비교를 전체 Docker 검사나 워크플로 실행으로 표현하지 않는다.

## 명시적 분류와 필터 위치 변경에 대한 추가 회귀

추가 독립 리뷰는 이름 추론만으로 복원되지 않는 운영자 분류를 확인했다. 예를 들어 원본 `/body/rows/0/label`에 secret 분류가 있고, 필터 후 `kept[0].label`을 Slack으로 보내면 분류와 public-only 정책 위반 후보가 유지되어야 한다. 필터링 이후 원래 0번 요소가 여전히 0번이라고 보장하지는 않는다.

미확인 컬렉션은 Aggregate의 기존 `includesDescendants` 후보 의미를 재사용한다. 여기에 **미확인 배열 인덱스와 이후 선택한 필드 이름**을 내부 경로로 구분해 저장했다. `/body/rows/(미확인 인덱스)/label`은 어느 원본 인덱스의 label 분류든 보존하지만, 무관한 password 형제 필드의 분류를 label 전송의 확정 정책 위반으로 올리지 않는다. 흐름 분석의 운영자 주석과 전송 정책의 분류가 같은 내부 경로 매칭을 사용한다. 정확한 데이터 존재·인덱스·실행은 계속 미확인이다.

새 회귀는 `row => true`, `row => row.keep`, `Boolean` 필터에 대해 secret/personal/internal 분류와 Slack public-only 정책을 함께 확인한다. 주석 유무, 무관한 형제 필드·다른 노드·접두사 충돌·이스케이프된 속성 이름·상위 객체 분류도 검사한다. 관련 총 184개 검사(전용 Code 17개 포함)가 통과했다. 후보 경로와 원문 필드 이름은 공개 결과에 노출하지 않는다. 이전 Docker 결과는 이 추가 수정의 실행 근거로 재사용하지 않으며 통합 담당자가 새 이미지로 다시 검사한다.

## 대표 원소 모델과 위치별 검증 근거 분리

후속 리뷰에서 0번 이외의 출력 인덱스, 일부 원소에만 분류 주석이 있는 배열, 중첩된 필터 결과를 합치는 분기의 공통 문제를 확인했다. 가상의 `/0` 필드로 가능한 원소를 표현하던 방식을 제거하고, 내부 `representativeElement`에 가능한 원소의 요약을 별도로 보관한다. `filter`·`map`·`flatMap`·`$input.all()` 및 배열 spread의 불확실한 원소를 이 모델로 전달한다. 크기 계산에는 이 대표 원소도 포함하므로 기존 추상 형태 예산을 우회하지 않는다.

정적인 출력 인덱스 0·1·7을 읽으면 같은 **가능 원소 집합**을 살피지만, 원출처에 해당 출력 인덱스를 다시 붙이지 않는다. 선택한 값의 존재·위치·상수는 미확인으로 유지한다. 원본의 `/rows/0` 주석처럼 일부 필드만 알려진 경우에는 `fieldsComplete`가 참이 아니므로 알려진 숫자 필드만을 완전한 배열로 취급하지 않는다. 알려지지 않은 나머지 원소의 민감 분류와 정책 위반 후보도 보존한다.

가능한 출처 경로와 요청한 출력 위치는 값 식별자에 포함한다. 따라서 한 단계와 두 단계의 필터 분기 결과가 중복 제거로 합쳐져 분류가 사라지지 않고, 같은 후보 출처를 가진 0번·1번·7번도 같은 구체 값으로 취급하지 않는다. IF에서 0번을 검사했다는 사실은 다른 위치의 검증 근거가 되지 않는다. 선택한 필드가 `label`이면 `password` 형제 필드의 분류는 계속 제외한다.

최종 전용 Code 검사 22개와 기존 흐름·AI·설정 검사까지 총 189개를 통과했다. 회귀에는 Code 내부 선택과 다음 노드의 `$json.result[1].label` 선택, 부분 원소 주석, 세 가지 필터 콜백, 중첩 분기의 internal·secret 동시 유지, 정상 공개 후보의 미확인 존재·위치, 실제 IF 경로의 검증 근거 분리가 포함된다. 이는 정적 분석기의 합성 회귀 검증이며 공개·사용자 워크플로 실행 결과가 아니다. 위의 이전 공개 비교 기록과 새 이미지 통합 검증은 구분한다.

## 분기와 구조가 불명확한 변환의 공통 규칙

대표 원소만으로는 필터 결과와 일반 배열을 합친 분기에서 구조가 사라질 수 있었다. 공통 `join`은 **하나의 값을 선택하는 대안 병합**과 **객체 필드·문자열·호출 인자의 의존성 집계**를 구분한다. 대안 병합은 제한된 `projectionAlternatives`를 보존하고, 이후 필드 선택과 컬렉션 콜백은 각 대안에 선택을 적용한 뒤 결과를 합친다. 따라서 `if`, 삼항식, `||`, `??`에서 대표 배열과 일반 배열, 서로 다른 대표 배열을 섞어도 같은 전달 규칙을 따른다. 객체에 배열 필드 하나가 있다는 이유로 객체 자체를 그 배열로 취급하거나, 직렬화된 문자열에 대표 원소를 복사하지 않는다.

삼항식의 조건은 별도 `projectionDependencies`로 유지하며 가능한 배열 원소로 취급하지 않는다. 선택 위치 다음의 실제 객체 키도 구분한다. 예를 들어 `kept[0]['0'].label`에서 첫 0은 출력 위치지만 두 번째 `'0'`은 원본 원소의 실제 속성 선택이다. 조건과 여러 번의 속성 선택이 섞여도 선택하지 않은 password 형제 필드의 분류를 label에 추가하지 않는다. 스칼라와 배열의 혼합은 실제 타입·존재 여부를 확정하지 않고, 모든 관측된 위험 후보와 불확실성을 유지한다.

입력 후보 경로는 출력 구조가 같다는 증거가 아니다. `JSON.parse(JSON.stringify(kept))[0].label`이나 미지원 호출의 결과는 원래 후보 selector를 유지하되 `projectionUnknown`으로 추가 좁히기를 중단한다. 파싱 결과의 `[0].label`을 원본 후보의 미확인 인덱스 뒤에 붙여 특정 원본 분류를 누락시키지 않는다. 반대로 이미 선택한 원본 `label`의 의존성 범위를 무관한 password 형제 필드로 넓히지도 않는다. 완전히 알려진 객체의 직렬화는 내부 `contentComplete`로 내용 분류만 유지하고, 출력 필드 구조나 파싱 성공을 주장하지 않는다.

형태 예산은 필드·대표 원소·대안·조건 의존성을 모두 계산한다. 반복 분기로 예산을 넘으면 구조를 단순화하고 기존 후보·제한 진단을 유지한다. 이 내부 메타데이터는 공개 결과에 직렬화하지 않는다.

`test/bounded-code-joins.test.mjs`의 9개 검사와 앞선 검사를 합쳐 관련 **271개**가 통과했다. 전용 컬렉션·병합 검사는 31개이며, 나머지는 흐름·AI·설정·전송·근거·정책 회귀다. 대안 순서 교환과 중복, 출력 위치 0·1·7, 다음 노드의 선택, 병합 이후 filter/map, 조건 의존성, 실제 숫자 속성, 주석 유무, JSON/미지원 변환, 정상 직렬화, 형태 예산 경계를 포함한다. 이전 이미지의 검증 기록을 이번 공통 병합 수정의 증거로 사용하지 않는다.

## 선택적 필드와 공통 구조 보존

분기 한쪽에서만 `{result: rows.filter(Boolean)}`를 만드는 경우도 가능한 result 구조를 유지해야 한다. 기존 `code_branch_field_optional` 포장은 필드 맵만 복사해 대표 원소·대안 정보를 잃었다. `src/workflow/value-shape.ts`의 공통 `preserveValueShape`로 선택적 필드, 컬렉션 조건 의존성 포장, bounded 결과, 인덱스 선택 포장 네 곳을 통일했다. 이 함수는 구조 정보만 보존하며 상태·존재·상수·검증 조건·출처·값 식별자는 포장 단계가 결정한다.

선택적 필드의 후속 선택도 존재 미확인·상수 미확인·검증 조건 없음 상태를 유지한다. 일반 공개 배열이라도 분기에 따라 필드가 없을 수 있다는 사실을 없애지 않는다. 재검토한 객체 spread의 알려진 필드 복사는 새 객체를 구성하는 작업이므로 대표 컬렉션 전체를 복사하지 않으며, JSON/불명 변환은 앞선 구조 단절 규칙을 그대로 유지한다.

추가 두 검사는 선택적 대표 배열, 병합한 배열, 다시 map한 배열, 이미 선택한 원소, 중첩 객체의 컬렉션을 다음 노드에서 읽는 경우를 포함한다. 인덱스 0·1·7과 주석 유무에서 internal·secret 후보와 정책 위반 후보가 유지되고, 무관한 password 형제 분류가 유입되지 않으며, 정상 공개 후보도 존재가 확정되지 않음을 확인했다. 관련 **273개** 검사(전용 컬렉션 22개·병합 11개 포함)가 통과했다.
